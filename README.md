# Lyric Room

**내 MP3에 가사와 배경을 더해, 나만의 음악 영상을 만드세요.**

Lyric Room은 브라우저에서 사용하는 로컬 음악 영상 편집기입니다. MP3 한 곡을 열고, 재생 시간에 맞춘 가사와 사진·영상 배경을 꾸민 다음 **1080p MP4**로 내보낼 수 있습니다.

계정이나 AI API 키 없이 사용할 수 있으며, 편집 내용은 컴퓨터에 자동 저장됩니다. 편집·재생·영상 출력 과정에서 앱이 미디어를 외부 서버로 전송하지 않습니다.

## 주요 기능

| 기능 | 할 수 있는 일 |
| --- | --- |
| 한 곡에 집중하는 편집 | MP3 한 곡을 프로젝트로 열고, 파일 메뉴에서 최근 프로젝트 전환 |
| 배경 꾸미기 | 사진·영상 불러오기, 밝기·흐림·확대·위치 조정, 영상 시작점·반복 설정 |
| 동기화 가사 | 시간별 원문·발음·번역 표시, 부드러운 위쪽 스크롤, 긴 간주 구간 안내 |
| 플레이어 꾸미기 | 앨범 커버·곡 이름·가수 표시, 색상·크기·모서리·투명도 조정 |
| 오디오 시각 효과 | 실제 음악에 반응하는 막대·스펙트럼 곡선, 색상·강도·빛 번짐 조정 |
| 직접 배치 | 미리보기에서 요소 이동·크기 변경, 속성 패널에서 수치 입력 |
| 로컬 자동 저장 | 편집을 0.75초 멈추면 저장, 저장 상태 표시, 프로젝트 다시 열기 |
| MP4 내보내기 | 1920×1080 · 30fps · H.264 영상과 AAC 오디오 출력 |

현재는 **MVP**이며, macOS 직접 실행과 Docker의 Linux ARM64 환경에서 검증했습니다. 여러 곡을 한 영상으로 합치기, 임의 레이어 추가·순서 변경, 키프레임, 단어 단위 노래방 강조, 유튜브 업로드는 지원하지 않습니다.

## 빠른 시작

### 방법 1: Docker로 실행

**Docker Desktop 또는 Docker Engine + Compose**가 설치되어 있으면 Node.js·FFmpeg·Chromium을 따로 설치하지 않아도 됩니다. Docker를 실행한 뒤 저장소를 내려받아 실행하세요. Git이 없다면 GitHub의 **Code → Download ZIP**으로 내려받고 압축을 푼 폴더에서 같은 Compose 명령을 실행할 수 있습니다.

```sh
git clone https://github.com/minyongP/lyric-room.git
cd lyric-room
docker compose up -d --build
```

**[http://127.0.0.1:4173](http://127.0.0.1:4173)**을 여세요. 첫 실행은 이미지와 Chromium을 다운로드하고 빌드하므로 시간이 걸립니다. 이후에는 `docker compose up -d`로 실행합니다.

```sh
docker compose logs -f     # 실행 로그 확인 (Ctrl+C로 로그 보기 종료)
docker compose down        # 앱 종료, 저장 데이터는 유지
```

최신 코드로 업데이트할 때:

```sh
git pull
docker compose up -d --build
```

기존 로컬 서버가 4173 포트를 사용한다면 종료하거나 프로젝트 폴더의 `.env`에 `LYRIC_ROOM_PORT=4180`을 적고 실행하세요. 이 경우 접속 주소는 `http://127.0.0.1:4180`입니다. 포트를 바꿀 때는 Compose 설정의 포트 매핑을 직접 수정하지 말고 이 변수를 사용하세요.

Docker 프로젝트는 전용 영구 볼륨에 저장됩니다. 기존 직접 실행의 `.local-data/`와는 별도이며, 백업·이전 방법은 [Docker 데이터 관리](#docker-데이터-관리)를 참고하세요.

### 방법 2: 직접 설치해서 실행

개발하거나 Docker 없이 실행하려면 다음이 필요합니다.

- Git
- Node.js **22.12 이상**과 npm
- **FFmpeg와 ffprobe** — 터미널에서 실행할 수 있도록 PATH에 등록되어 있어야 합니다. FFmpeg에는 `libx264`와 AAC 인코더가 필요합니다.
- Playwright Chromium — 아래 명령으로 설치합니다.

macOS에서 Homebrew를 사용한다면:

```sh
brew install ffmpeg
```

```sh
git clone https://github.com/minyongP/lyric-room.git
cd lyric-room
npm ci
npx playwright install chromium
npm run dev
```

브라우저에서 **[http://127.0.0.1:4173](http://127.0.0.1:4173)**을 여세요. 앱을 사용하는 동안 서버를 실행해 두고, 종료할 때는 `Ctrl+C`를 누릅니다.

두 실행 방식 모두 기본 설정에서는 이 컴퓨터에서만 접속할 수 있습니다. 처음 설치할 때는 패키지와 Chromium 다운로드를 위한 인터넷 연결이 필요합니다. 폰트는 패키지에 포함됩니다.

## 사용 방법

1. **음악 열기** — 시작 화면 또는 **파일 → 음악 파일 열기**에서 MP3 한 곡을 선택합니다.
2. **장면 꾸미기** — 왼쪽의 **배경 / 가사 / 플레이어 / 시각 효과**를 선택하고 오른쪽 속성을 조정합니다. 미리보기에서 요소를 드래그하거나 우하단 손잡이로 크기를 변경할 수도 있습니다.
3. **가사 넣기** — 가사 편집의 **JSON 가져오기**로 파일 또는 텍스트를 적용합니다. 구절별 시간과 내용은 표에서 직접 수정할 수 있습니다.
4. **재생하며 확인하기** — 진행 바에서 시간을 이동하고 **플레이 화면**으로 감상합니다. 이전·다음 버튼은 현재 곡의 **이전·다음 가사 구절**로 이동합니다.
5. **영상 저장하기** — **영상 내보내기**를 실행한 뒤, 완료되면 **MP4 저장**으로 다운로드합니다.

편집은 자동 저장됩니다. 상단의 저장 상태를 확인하고, 다음에 사용할 때는 **파일 → 최근 프로젝트**에서 다시 여세요.

## AI로 가사 JSON 준비하기

앱의 **가사 → AI 요청 가이드**에서 **한국곡 / 영어곡 / 일본곡 / 기타**를 선택하면 언어별 요청문을 복사할 수 있습니다. 현재 곡 길이와 앱이 사용하는 JSON 규칙도 함께 포함됩니다.

1. 외부 AI에 MP3와 사용할 원문 가사를 직접 제공합니다.
2. 앱에서 복사한 요청문으로 구절별 시간, 필요한 발음·번역을 정리하도록 요청합니다.
3. 결과를 **JSON 가져오기**로 적용하고 실제 재생과 비교하며 시간을 보정합니다.

Lyric Room 자체에 AI 모델이나 자동 전사·정렬 기능이 내장된 것은 아닙니다. 외부 AI의 오디오 분석 지원 여부와 시간 정확도는 사용하는 서비스에 따라 다릅니다. 외부 서비스에 제공하는 파일은 사용자가 직접 선택합니다.

요청문 작성 예시는 [AI 프롬프트 가이드](examples/ai-prompt.md), 가져오기 예시는 [가사 JSON](examples/lyrics.json)을 참고하세요.

### 가사 JSON 형식

아래 가사는 형식 설명을 위해 작성한 예시입니다.

```json
{
  "schemaVersion": 1,
  "lyrics": [
    {
      "start": 12.5,
      "end": 17.8,
      "original": "바람이 머문 자리",
      "pronunciation": "발음 (선택)",
      "translation": "번역 (선택)"
    }
  ]
}
```

| 필드 | 의미 |
| --- | --- |
| `start` | 구절이 시작되는 시간, 초 단위 |
| `end` | 구절이 끝나는 시간, 초 단위 |
| `original` | 표시할 원문 가사 |
| `pronunciation` | 발음 표기, 생략 가능 |
| `translation` | 번역, 생략 가능 |

구절은 시작 시간순으로 작성하며, 서로 겹치거나 곡 길이를 벗어나면 안 됩니다. `start <= 현재 시간 < end`인 구절을 강조합니다.

가사는 약 0.55초 동안 위로 부드럽게 이동합니다. 곡 중간에서 앞 구절의 끝과 다음 구절의 시작 사이가 **5초 이상**일 때만 **간주 중** 안내를 표시합니다. 곡 시작·끝과 5초 미만의 공백은 비워둡니다. 간주 여부는 음성 분석이 아닌 입력한 시간 간격을 기준으로 판단합니다.

## 지원 파일과 영상 출력

| 용도 | 지원 형식 |
| --- | --- |
| 음악 | MP3, 프로젝트당 한 곡 |
| 배경 | JPEG, PNG, WebP, H.264 MP4 |
| 앨범 커버 | JPEG, PNG, WebP |
| 출력 영상 | MP4 · 1920×1080 · 30fps · H.264 (`yuv420p`) · AAC 192kbps |

파일당 최대 512MB, 음원·영상 길이 최대 2시간, 이미지 최대 8192px를 허용합니다. 입력 상한까지의 성능을 보장하는 것은 아니며 출력 시간은 곡 길이·배경 영상·기기에 따라 달라집니다.

배경 영상의 소리는 재생하거나 출력하지 않습니다. 미리보기 볼륨 조정은 출력 영상의 음량에 영향을 주지 않습니다.

출력에는 **가사·배경·커버·곡 정보·진행 바·시각 효과**가 포함됩니다. 재생 조작 버튼과 편집용 선택 테두리는 포함하지 않습니다. 시각 효과의 선 모드는 음성 파형이 아닌 주파수 스펙트럼 곡선입니다.

한 번에 하나의 영상을 출력할 수 있으며 취소 후 다시 실행할 수 있습니다. 출력 시작 시점의 편집 내용을 사용하므로, 출력 중 추가로 편집해도 진행 중인 영상은 바뀌지 않습니다.

## 자동 저장과 백업

선택한 미디어는 프로젝트 폴더로 복사되며 원본 파일은 변경하지 않습니다. 직접 실행의 기본 저장 위치는 실행 디렉터리의 `.local-data/`이며, Docker에서는 같은 구조를 `/data` 볼륨에 저장합니다.

```text
.local-data/
├── projects/
│   └── <프로젝트 ID>/
│       ├── project.json    # 가사와 편집 설정
│       └── assets/         # 복사한 음원·배경·커버
└── exports/                # 완료된 출력 영상
```

- **자동 저장:** 편집을 0.75초 멈추면 저장합니다. 수동 저장도 가능하며, 다른 음악을 열기 전에 현재 변경 내용을 저장합니다.
- **입력 오류:** 가사 시간 등이 잘못되면 저장을 보류하고 마지막 정상 저장본을 유지합니다. 값을 수정하면 자동 저장을 재개합니다.
- **저장 실패:** 오류 안내의 **다시 저장**으로 재시도할 수 있습니다. 저장하지 못한 변경이 있으면 프로젝트 전환 또는 페이지 종료 시 알립니다.
- **백업:** 서버를 종료한 뒤 `.local-data/` 폴더 전체를 복사하세요. `project.json`만 복사하면 미디어는 함께 옮겨지지 않습니다.

사용자 미디어, 로컬 프로젝트, 출력 영상은 Git 추적에서 제외됩니다. 단일 프로젝트 패키지의 가져오기·내보내기는 아직 지원하지 않습니다.

### Docker 데이터 관리

Compose의 `lyric-room-data` 볼륨은 컨테이너를 재생성하거나 `docker compose down`을 실행해도 유지됩니다. **`docker compose down -v`는 저장 데이터까지 삭제하므로 사용하지 마세요.**

편집·출력을 마친 뒤 컨테이너를 멈추고 백업할 수 있습니다. 다음 명령은 프로젝트 폴더에 `lyric-room-backup/`을 만듭니다.

```sh
docker compose stop
docker compose cp lyric-room:/data ./lyric-room-backup
docker compose start
```

기존 직접 실행의 프로젝트를 Docker로 이전하려면, 로컬 서버를 종료하고 **비어 있는 새 Docker 볼륨**에 데이터를 복사하세요. 기존 Docker 프로젝트가 있다면 먼저 백업하세요.

```sh
docker compose create
docker compose cp ./.local-data/. lyric-room:/data/
docker compose run --rm --no-deps --user root lyric-room chown -R node:node /data
docker compose up -d
```

백업을 새 볼륨에 복원할 때는 위 복사 명령의 `./.local-data/.`를 `./lyric-room-backup/.`로 바꿉니다. 데이터는 실행한 Compose 프로젝트에 연결되므로 폴더 이름이나 `-p` 프로젝트 이름을 바꾸면 별도 볼륨이 사용될 수 있습니다.

## 문제 해결

| 증상 | 확인할 내용 |
| --- | --- |
| 영상 내보내기를 사용할 수 없음 | `ffmpeg -version`, `ffprobe -version` 실행 여부를 확인하고 `npx playwright install chromium`으로 Chromium을 설치하세요. |
| 서버가 포트 충돌로 시작되지 않음 | 직접 실행은 `PORT`, Docker는 `.env`의 `LYRIC_ROOM_PORT`를 변경하세요. |
| Docker 데몬에 연결할 수 없음 | Docker Desktop 또는 Docker Engine이 실행 중인지 확인하세요. |
| 자동 저장이 보류됨 | 안내된 행의 가사 시작·종료 시간과 필수 입력값을 수정하세요. |
| 자동 저장이 실패함 | 로컬 서버가 실행 중인지 확인하고 **다시 저장**을 누르세요. |
| 배경 MP4를 열 수 없음 | 영상 코덱이 H.264인지 확인하세요. 모든 MP4 코덱을 지원하지는 않습니다. |
| 긴 가사가 잘림 | 글자 크기를 줄이거나 가사 패널을 확대하세요. |
| 출력 중 앱이 종료됨 | 출력을 다시 시작하세요. 이어 만들기는 지원하지 않으며, 기존 완료 파일은 보존됩니다. |

## 개발 및 기여

프런트엔드는 **React · TypeScript · Vite**, 로컬 서버는 **Node.js · Express**를 사용합니다. 미리보기와 출력이 같은 Canvas 렌더러를 사용하며, Chromium에서 만든 프레임을 FFmpeg로 인코딩합니다.

| 경로 | 역할 |
| --- | --- |
| `src/editor/` | 편집 UI, 미리보기, 자동 저장 |
| `src/shared/` | 프로젝트와 가사 데이터 검증 |
| `src/scene/` | 미리보기·영상 출력 공통 Canvas 렌더러 |
| `src/audio/` | FFT 기반 주파수 분석 |
| `server/` | 로컬 파일 저장과 HTTP API |
| `server/export/` | Chromium 렌더링과 FFmpeg 인코딩 |
| `tests/` | 단위·통합·브라우저 테스트 |

검증 명령:

```sh
npm run fixtures       # 자체 생성한 테스트 미디어 준비 (Git 제외)
npm test               # 단위·통합 테스트
npm run test:e2e        # 독립 로컬 서버를 사용하는 브라우저 테스트
npm run build          # TypeScript 검사와 프로덕션 빌드
```

출력 파일을 별도로 검증할 때는 예상 길이를 초 단위로 전달합니다.

```sh
npm run verify:export -- /path/to/video.mp4 180
```

검증 환경과 범위는 [검증 기록](docs/verification.md)을 참고하세요. macOS 직접 실행과 Docker Desktop의 Linux ARM64 컨테이너를 검증했습니다. Windows 및 Linux AMD64는 별도 검증하지 않았습니다.

버그 제보와 개선 제안은 [GitHub Issues](https://github.com/minyongP/lyric-room/issues), 코드 변경은 Pull Request로 보내주세요. 버그 제보에는 운영체제, Node.js·FFmpeg 버전, 재현 순서와 오류 메시지를 포함하면 도움이 됩니다. 코드 변경 시 관련 테스트와 빌드를 확인해 주세요.

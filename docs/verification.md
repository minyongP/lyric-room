# MVP 검증 기록

2026-10-09, macOS 로컬 환경에서 검증했습니다. 아래 내용은 실행한 범위이며 모든 운영체제나 2시간 상한까지의 성능 보장을 뜻하지 않습니다.

## 실행 환경

- Node.js 24.12.0 / npm 11.6.2
- 저장소 lockfile 기준 React, Vite, TypeScript
- Playwright Chromium, PATH에 설치된 FFmpeg/ffprobe
- 개발 서버 127.0.0.1:4173, 독립 E2E 서버 4174, 프로덕션 빌드 서버 4175

자동 저장 추가 후 재검증 결과: **단위·통합 테스트 34개, 브라우저 테스트 19개 통과**, TypeScript 검사와 프로덕션 빌드 통과.

## 확인한 동작

- 한글·공백 이름 MP3 열기, 실제 재생/탐색, 곡 정보·가사 편집
- 프로젝트 저장 후 페이지 재실행과 최근 프로젝트 열기
- 0.75초 자동 저장, 지연된 요청의 순차 처리와 최종 편집 보존, 다른 음악을 열기 직전 저장
- 잘못된 가사 시간은 저장 보류 후 수정 시 복구, 저장 실패 후 수동 재시도
- 가사 시간 경계와 공백 구간, 겹침·잘못된 시간 거부
- FFT의 무음/단일 주파수 입력과 프레임 선택
- 경로/자산 검증, Origin·세션 토큰 보호, 숨김 데이터 폴더의 미디어 Range 응답
- 사진 배경 / H.264 영상 배경 실제 1080p 출력, 영상 루프 프레임 일치와 무음
- 출력 취소·재시도, 실패 시 거짓 완료 방지, 정상 출력 보존
- 첫 프레임의 한글·일본어 폰트 준비 (대체 글꼴 문제 재현 후 수정)
- 늦게 도착한 배경 업로드가 제거를 되돌리지 않음, 배경·커버 동시 업로드의 독립 적용
- 현재 보이지 않는 뒤쪽 가사의 넘침도 출력 전 검사
- 분석 중 취소 즉시 처리, 별도 미리보기 분석 소비자는 유지
- 390px 화면의 가로 넘침 없음
- TypeScript 검사와 Vite 프로덕션 빌드, 빌드된 페이지로 MP4 출력

## Docker 추가 검증

macOS의 Docker Desktop에서 Linux ARM64 이미지를 빌드하고 별도 Compose 프로젝트·4186 포트로 확인했습니다. 기존 로컬 프로젝트 데이터는 사용하지 않았습니다.

- `docker compose config`: 기본 및 사용자 지정 포트, localhost 바인딩, 영구 볼륨, init, 1GB 공유 메모리 설정 확인
- Node 24 / Debian Bookworm 기반 이미지 빌드 및 헬스체크 통과
- 컨테이너의 비루트 사용자 실행, 이미지에서 `.local-data`·`.git` 제외 확인
- 브라우저에서 MP3 업로드, 메타데이터 자동 저장, 새로고침 후 복원
- 외부 Origin 요청에 403 응답
- 실제 3초 음원 + 반복 MP4 배경 출력: 1920×1080, 30fps, H.264 + AAC (컨테이너 출력 길이 3.033초)
- 컨테이너 종료·삭제·재생성 후 두 테스트 프로젝트 보존
- 중지된 컨테이너에서 데이터 폴더 백업 확인
- 단위·통합 테스트 34개, TypeScript 및 Vite 빌드 재통과

Compose 설정은 [Playwright Docker 안내](https://playwright.dev/docs/docker)를 참고했습니다. Windows와 Linux AMD64의 별도 실행 검증은 하지 않았습니다.

## 실제 영상 출력

직접 생성한 테스트 음원·배경만 사용했습니다. 테스트 미디어는 Git에 포함하지 않습니다.

| 입력 | 출력 검증 |
| --- | --- |
| 3초 MP3 + PNG | 1920×1080, 30fps, H.264 yuv420p + AAC, 3.000초 |
| 3초 MP3 + 2초 반복 MP4 | 동일 사양, 3.000초 |
| 180초 MP3 + PNG | 동일 사양, 180.000초 |

3분 출력은 프레임을 FFmpeg에 순차 전달했으며 PNG 프레임 파일을 쌓지 않았습니다. 별도 자원 샘플링 141초 구간에서 부분 출력 파일은 최대 약 3.25MiB였습니다. 다른 E2E Chromium 프로세스가 함께 실행되어 합산 메모리 관측값은 이 앱 단독 사용량으로 해석할 수 없습니다. 처리 시간·크기는 실제 음악과 배경에 따라 달라집니다.

프로덕션 출력의 0.5 / 1.3 / 1.5 / 2.1초 프레임을 공유 렌더러와 비교했습니다. 0–255 RGB 평균 절대 차이는 각각 1.316 / 1.259 / 1.298 / 1.290으로, 손실 압축에 따른 차이를 포함합니다. 가사 구절 사이 공백과 배경 루프 이후도 포함한 비교입니다.

원본 MP3와 출력 AAC를 24kHz 모노 PCM으로 디코딩한 후 ±100ms 범위에서 1ms 단위로 비교했습니다. 3초 생성 음원의 최소 오차 지점은 **0ms**, 평균 제곱 오차는 약 6.33×10⁻⁹였습니다. 임의의 모든 음원에 대한 검증은 아닙니다.

## 재현

```sh
npm ci
npx playwright install chromium
npm run fixtures
npm test
npm run test:e2e
npm run build
# 별도 터미널에서 npm run dev
npx tsx scripts/smoke-export.ts --long
npx tsx scripts/smoke-export.ts --video
APP_URL=http://127.0.0.1:4173 npx tsx scripts/compare-frames.ts
```

`compare-frames.ts`는 바로 앞 `smoke-export.ts --video`가 저장한 프로젝트와 출력 파일을 사용합니다.

## 남아 있는 범위

- macOS 직접 실행과 Docker Desktop의 Linux ARM64 컨테이너를 검증했습니다. Windows와 Linux AMD64는 별도 검증하지 않았습니다.
- AI 가사 자동 생성/정렬은 포함하지 않으며 외부 AI가 만든 JSON을 검증해 가져옵니다.
- 강제 종료한 출력의 이어 만들기는 지원하지 않습니다. 다시 출력해야 하며 완료 파일은 보존됩니다.
- 프로젝트 이동은 `.local-data` 폴더 백업 방식입니다. 단일 프로젝트 패키지 가져오기/내보내기는 후속 범위입니다.
- 기본 레이어의 배치·크기·스타일을 조절합니다. 임의 레이어, 키프레임, 여러 곡 조합은 포함하지 않습니다.
